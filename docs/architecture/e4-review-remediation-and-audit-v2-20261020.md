## Reparaciones realizadas sin Codex Builder
1. El handoff rechaza cualquier expresión dependiente con nombre propio capitalizado que no se corresponde con la identidad canónica autenticada. Esto es un **fail-closed conservador**, no un resolvedor general de alias: los alias no verificados deben quedar pendientes, no redirigirse por descarte. Dos auditores semánticos no sustituyen esta comprobación determinista. Pruebas de diferentes nombres propios en Core y un recorrido desde `build_runtime_from_environment` con Marta en Core y Ana en el segmento Task aseguran que no se guarda ninguna Task.
2. El script Chromium comprueba durante el envío que existe un `role=progressbar`, escala 0–100, porcentaje visual coherente y círculo SVG. El E2E Chromium/n8n/Writer con modelo grabado **PASS**, `progressDonut.present=true`, autenticación local 403, dos recibos Core, notas y grafo después de recargar, replay sin diferencias Markdown. El valor inicial observado fue 0; este test no demuestra una animación temporal ni p95 de actualización del progreso.
3. El supervisor dispone de paquetes de evidencia especializados: un clasificador determinista entrega el diff relevante y un **manifiesto completo de todos los archivos cambiados**; cada auditor conserva lectura real del checkout entero y el hash de snapshot. Cuando cambia Core, Writer, identidad, E3, schema, runtime o permisos, se entrega a los cuatro **el diff completo** sin especialización de recorte. Todos los archivos no seleccionados permanecen legibles en modo read-only, con permisos nativos sin red ni secretos.
4. `plan --implemented-by chatgpt --against <sha-del-audit-anterior> --incremental-from <job-previo>` valida una auditoría anterior con los cuatro PASS, el commit/snapshot Git previo sin cambios y los cuatro JSON de dictamen, su ubicación y consistencia. Para cambios **exclusivamente de tests**, se reaudita Testing; para documentación no contractual, Generality y Quality; en todo otro caso se vuelven a ejecutar los cuatro. Los roles sin nuevo modelo se identifican expresamente `inherited_prior_pass` y no figuran como nuevas sesiones Codex; la revalidación se repite al ejecutar y ante pausas. **No hay herencia cuando un auditor anterior falló o quedó bloqueado**, como sucedió en E4. No hay Builder automático en una pasada ChatGPT de una ronda.
5. Las baterías incluyen tests adversariales de modificación del checkout previo, falsificación de recibos, políticas críticas, diffs por especialidad, archivo crítico no rastreado y selección incremental. El test especializado forma parte del gate transversal; no hay heurísticas con nombres de casos en código de producto. El supervisor v2 es él mismo código sensible que requiere **nueva auditoría completa antes de uso autónomo prolongado**.
