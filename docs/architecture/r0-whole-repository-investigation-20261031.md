## Thin orchestrator objective (no new service or duplicate port)

**Observed current source when enabled:** `RuntimeComposition` does preliminary read planning → P4 independently selects capability/scopes → source/group/Tasks/Event branches run different validators/planners → Core/Apps sometimes receive different context → E3 writes and UI projects. Some of these internal paths reject valid sources before reaching their already-existing generic Core/App owner.

**Intended reuse-only path:**

```text
immutable user source + actor + bounded clock/history
    ↓ existing ExecutionContext and typed StageSpecs / App catalog
AI stage interpretation → typed proposals + original source evidence
    ↓ Core validates provenance, groups, identities, ambiguity, owner
existing RequestPlan → Core/E3 or registered App lifecycle ports
    ↓ canonical physical Markdown + readback + delivery/replay receipts
visible Notes / Calendar / response / trace
```

The coordinator is responsible for context transport, dependency ordering, retries/receipt safety and observable stage success. **No coordinator branch on user phrase, family/object/person, Note type, list size, grammar form or hard-coded Core+Tasks/Events+Tasks combination.** Semantic interpretation belongs to AI; source/identity/write permission always remains verified and fail-closed. Do not mistake separate trust-boundary checks for accidental duplication.
