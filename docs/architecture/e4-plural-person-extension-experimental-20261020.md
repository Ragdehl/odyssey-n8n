# E4 — N:M Person→una Task, segmento experimental SIN aceptación (20-10-2026)

**Motivo:** campañas NUEVAS con GPT REAL el 20-10 detectaron que frases de una sola obligación con dos personas («conocí a Ana y a Luis; mañana debo llamar a ambos/los dos») devolvían `needs_attention` sin creación. Este comportamiento es seguro pero no satisface la intención. No debe etiquetarse E4 plural PASS.

## Hallazgos basados en evidencia
- `odyssey_light_capability_route_v1` con GPT real propuso correctamente dos scopes, Core + Tasks dependiente.
- Propuesta N:M `odyssey_dependent_graph_partition_v1` y su auditor independiente con GPT real dieron un DAG aprobado **una vez**, con edges Ana→los dos y Luis→los dos (de un mismo grupo Core). En otras generaciones reales el auditor rechazó la fuente con `DEPENDENT_N_GRAPH_SOURCE_UNVERIFIED` antes de guardar nada.
- El Core Planner + Writer y la guarda E3 ya pueden materializar **una Task con dos links canónicos**: test físico de Markdown con dos Tasks conocidas, sin escritor nuevo ni schema adicional.
- Se amplió el carrier read-only `TaskPersonReferenceSet`, preflight conjuntivo de Core `DependentReferenceSetGuard`, dos auditorías semánticas del conjunto, `DomainInterpretation` con dos evidencias y asociación de un grupo E3 a varios edges del mismo origen (E3 manifiesto lleva índices de grupos únicos, mientras E2 conserva ambas pruebas individuales).
- En un ensayo GPT real de la variante literal «llamar a Ana Ejemplo y a Luis Ejemplo» se observó **una Task con ambas referencias y replay estable**. Eso no acredita las demás formulaciones.
- Otros ensayos reales devolvieron `partial / DEPENDENT_N_CANONICAL_EDGE_UNVERIFIED` después de materializar ambas Person pero sin Task. Una inspección de recibos mostró **dos pruebas action-bound Core existentes** con la forma correcta para Ana y Luis, pero el graph propuso en ocasiones una expresión dependiente que `supported_anaphoric_form` no admitía. Se añadieron cardinales cerrados por lengua, incluidos «los dos», «a los dos» y «a ambos», con cotejo estricto de cardinalidad frente al número de recibos. En otra ejecución faltó una coincidencia única de referencia física. **Aún no se ha demostrado tasa estable de éxito con GPT real**.
- Todos los rechazos conocidos impidieron la creación de una Task con una persona incorrecta; algunas ejecuciones sí conservaron Persons ya materializadas y devolvieron `partial` correctamente: no son rollbacks atómicos de múltiples Notes.
