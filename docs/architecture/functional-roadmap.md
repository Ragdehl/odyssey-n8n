**Product invariant (26-10):** la aplicación final debe instalarse y funcionar en el móvil, con notas Markdown y estado duradero en almacenamiento privado **local por perfil**, sin exigir Raspberry/n8n/nube. acceptance contract: [Post-UI2 conversational schema evolution, section C](post-ui2-note-creation-and-schema-evolution.md#contrato-de-implementación-acordado-para-la-siguiente-fase-24-10-2026).
Upcoming first-party capabilities (recordatorios → location → Projects/Gantt) and UX standards: [near-term product backlog](near-term-product-backlog-20261025.md).
This is the *canonical next-step owner*; historic C4 latency/worktree/audit
notes below are NOT current blockers or an instruction to restart old work.

- **UI:** one AI-assisted «Modelo de notas» surface in Notes, deep-link from
  Chat; card preview, human-readable reasons, no technical «filterable» toggle;
  all newly offered properties must actually support appropriate queries.
- **One approval, autonomy after that:** confirmed schema scope authorizes
  unattended, grounded and reversible per-note enrichment. **No one-click-per-note,
  no repeated page approvals.** If entity identity can be independently proven,
  automatic creation/reuse is allowed after dedup; group only unresolved identities
  and contradictory sources for optional user review. Do not overwrite user-owned
  values or reclassify existing notes. See the [autonomy policy](post-ui2-note-creation-and-schema-evolution.md#decisión-de-producto-autonomía-por-defecto-y-excepciones-agrupadas-26-10-2026).
- **Properties:** scan existing notes of the affected type and backfill only
  evidenced values using E3; dates may have known year/month/day components
  without invented precision; age is derived, not a duplicate property.
- **Types:** scan *canonical existing facts from all note types* on demand for
  potential new entities. Do NOT precompute latent types or build speculative
  `PendingReference` classification. Keep actual pending references when Core
  really could not resolve an identity. No fuzzy create/relink or broad string
  replacement.
- **Technical priority:** base schema v3 and App extensions are composed at
  startup; validation currently requires exact physical `schema_version`.
  For compatible optional additions, do not increment all note format versions:
  establish separately versioned user registry + atomic composed snapshots,
  rollback and backward compatibility first. Use bounded parallel *analysis*,
  durable resumable job progress and Core/E3 guarded *writes*; fix global index
  wait behavior before promising nonblocking unrelated queries.

## Always-preserved product and validation contracts

1. **Local-first canonical Markdown / Core/E3** own identities, facts, target authorization and mutations. Router/Temporal/Apps provide bounded untrusted interpretation. `config/note-schema.json` owns exact machine schema.
2. **Generality:** candidates↔facts may be N:M; no per-phrase/name, note type, language or fixed participant/candidate-count exceptions. Preserve source scope, unknown/pending evidence, typed identity create vs complete-set literal distinction.
3. **No hidden deployment authority:** Git commit, successful offline tests, DEV deployed marker, authenticated browser E2E and PROD are different claims. Model-facing production changes require bounded authorized real-model evidence with the actual selected model/effort.
4. **Safety:** no unapproved mutation of PROD or private data, no secret logging, no forced Git pushes, destructive migrations or silent merge/deploy, preserve concurrent worktrees.
